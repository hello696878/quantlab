# QuantLab — PBO & CSCV Policy (Phase 53.0)

The exact conventions behind every CSCV split and PBO number in the
Overfitting Diagnostics Lab.  Companion:
[`BACKTEST_OVERFITTING_DIAGNOSTICS_LAB.md`](BACKTEST_OVERFITTING_DIAGNOSTICS_LAB.md).

## 1. Observation alignment

Strict identical alignment: every candidate supplies the same ordered,
strictly-increasing timestamps (one timezone convention) and the same number
of finite per-period returns.  Missing values are rejected — never
forward-filled, never imputed; timestamps are never fabricated.

## 2. Block construction

S chronological, contiguous subperiods (S even, 4 ≤ S ≤ 12), built with
`numpy.array_split`: sizes differ by at most one and **earlier blocks take
the extra observation** (documented determinism).  Every observation belongs
to exactly one block; nothing is dropped; block boundaries (start/end index,
size) are recorded on the run.  At least 4 observations per block are
required at creation.

## 3. Combination generation

All C(S, S/2) in-sample block choices, generated by
`itertools.combinations(range(S), S/2)` in lexicographic order — fully
deterministic.  **No sampling and no truncation exist in v1**; a
configuration whose combination count would exceed 924 (= C(12,6)) is
rejected with a 422 at creation.

## 4. IS/OOS complement

For each combination, the in-sample set is the concatenation of the chosen
S/2 blocks and the out-of-sample set is exactly the complementary S/2
blocks.  Because all combinations are enumerated, the design is
combinatorially symmetric: every combination's complement also appears as
its own combination.

## 5. Selection metric and ranking

The configured metric (`mean_return`, `median_return`, or `sharpe_like`;
higher is better; per-period, non-annualized) is computed for every
candidate on the IS set and again on the OOS set.  The IS-best candidate is
selected.  OOS ranks are **ascending with average ties: rank 1 = worst
measured OOS candidate, rank N = strongest measured OOS candidate**, where N
counts candidates whose OOS metric is defined in that split.  The convention
never flips.

## 6. Relative rank and lambda

```
omega  = oos_rank / (N + 1)          # strictly inside (0, 1)
lambda = ln( omega / (1 - omega) )
```

The N + 1 denominator avoids exact 0 and 1.  λ < 0 means the selected
candidate landed in the bottom OOS half; λ > 0 the top half; λ = 0 exactly
the middle (possible only through average ties).

## 7. PBO boundary convention

```
PBO = (# valid splits with lambda < 0) / (# valid splits)
```

**λ = 0 counts in the denominator but never as overfit** — the documented
boundary convention, asserted by tests.  The λ distribution additionally
reports `fraction_at_zero`.

## 8. Ties

Exact IS ties for the top metric select the lexicographically smallest
candidate_id (candidates are globally pre-sorted by id) and set
`tie_in_sample`; OOS value ties share average ranks and set
`tie_out_of_sample`; both counts surface in the aggregate.  Nothing is ever
chosen randomly.

## 9. Invalid splits

A split is invalid when every candidate's IS metric is undefined or when the
selected candidate's OOS metric is undefined (e.g. constant returns under
`sharpe_like`).  Invalid splits are **recorded with their reason and
excluded from the PBO denominator** — never silently dropped.  A run whose
every split is invalid fails honestly.

## 10. Combination limits

S_MIN = 4, S_MAX = 12, MAX_COMBINATIONS = 924, at least 4 observations per
block, 2–24 candidates, 24–2000 observations.  Configurations outside these
bounds are 422s, and no approximation mode exists.

## 11. What PBO does NOT prove

PBO estimates how often the in-sample selection landed in the bottom OOS
half **under this universe, metric, and block count**.  A low PBO is a lower
estimated selection-overfitting frequency under that configuration — it is
not robustness, not out-of-sample profitability, not evidence the strategy
works, and not a substitute for interval-aware validation (purging/embargo
live in the Model Validation Lab).  Comparing PBO across different
universes, metrics, block counts, or windows is flagged as not directly
comparable.
